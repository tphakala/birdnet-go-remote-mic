# internal/AGENTS.md

Rules for the packages under `internal/`. The root `AGENTS.md` applies as
well. Every package has a doc comment, and `go doc ./internal/<pkg>` is the
authoritative description of what it does; this file keeps what a change must
not break.

## Packages

- `audio`: `Source` (`Negotiated`/`Read`/`Close`) delivering S16LE periods.
  `OpenCapture` tries S16LE, S32LE, S24_LE, S24_3LE, downconverting to S16,
  and refuses a rate mismatch (never resample silently). Devices bind by
  stable USB identity, not ALSA card index. `fanout.go` splits one capture
  into per-stream channel subsets.
- `pipeline`: `Stage` turns periods into RTP payload frames: `NewPCM` (L16)
  and `NewOpus` (960-sample frames). `Frame.Captured` is capture time. `Run`
  takes a `Gate` (`Feed.Session`, active flag plus play session): a period
  read with no client playing is discarded unencoded. The play session
  advances only when the first client joins an idle stream, and Opus resets
  its encoder only on a session change, so a second client joining or a
  client leaving while others play never touches the encoder. The fan-out
  sends an idle stream nothing (gated on `Feed.Session`), so an idle stage
  blocks in its read, and tags each period with its session: a stage drops
  periods, and the feed frames, of an earlier session.
- `rtspserver`: minimal RTSP server; up to `maxClients` (8) clients play one
  path at once. SETUP echoes client-chosen interleaved channels and takes
  nothing; PLAY subscribes to the track's `Feed` (453 at the cap, 404 once
  the feed is closed) and returns RTP-Info. `writer.go` is the single writer
  per connection, each with its own SSRC, sequence and timestamp. `Feed` is a
  broadcast: `Push` copies the payload once and offers it to every
  subscriber's bounded queue without blocking, so a slow client drops only its
  own frames, and buffers nothing while no client is playing. The epoch and
  the subscriber list live in one copy-on-write snapshot; never mutate a
  published `subs` slice.
- `announce`: DNS-SD advertisement only (brutella/dnssd).
- `mgmtapi`: GENERATED by oapi-codegen from `api/openapi.yaml`. Never edit by
  hand; see the root file's Management API conventions.
- `mgmtserver`: the management API server, adapting a `Provider` into the
  generated contract.
- `mgmtcert`: self-signed TLS cert, regenerated when missing, expired, or
  wrong names. A custom installed cert is pinned, and a pinned file that
  exists but cannot be read is never overwritten (the API stays off and
  `cmd/remotemic` retries it in the background until the file reads again).
- `auth`: one shared token gates HTTP (Bearer) and RTSP (Digest). Empty token
  means open access. `Guard` keeps the token and its generation in one
  `atomic.Pointer`, so a reader never sees a new token with an old generation.
- `sse`: platform-neutral SSE transport. Producers implement `Source` and
  import `sse`, never the reverse. A producer that works only while it has
  a subscriber also implements `Named`, so a request whose `?events=`
  filter excludes its events never subscribes it (the levels hub does).
- `levels`: per-device peak/RMS metering, central sampler, fan-out.
- `notify`: in-memory notification center (bounded ring plus active
  conditions), RAM-only by design. Leaf package; emitters depend on
  `Publisher`, and a nil `*Center` is a no-op.
- `monitor`: condition monitors (audio signal, host health) and the
  `Settings`/`SettingsFrom`/`Monitors.Apply` seam fed on every reload.
- `reload`: pure, platform-neutral planning of live reconciliation to a new
  config. Keep it pure.
- `sysinfo`: `/proc`, `/sys`, statfs readers for `GET /system` and the host
  monitor. Parsers are platform-neutral; readers are Linux-only.
- `config`: YAML config and strict `Validate`; invalid input fails loudly at
  startup, never degrades silently. `Enabled` and `QuietAlert` are `*bool`
  (nil means on). The legacy flat device form migrates to `streams:` on load;
  `Save` always writes the nested form.
- `service`: installs a systemd unit running as a least-privilege system
  user, plus the root updater's path and oneshot units
  (`remote-mic-update.path`/`.service`). It refuses a bin directory anyone
  but root can write before writing anything, replaces (never follows) a link
  at the bin path, and leaves the updater units out (with a warning) when the
  installed binary still fails the root-only check. Under the bin lock it
  clears the kept copy (`.prev`) of an interrupted update before it replaces
  the binary and its journal (`<bin>.pending`) after; it also refuses a config or
  state file with a second hard link instead of chowning it, and a config or
  state directory that is the bin directory or one above it (compared by
  identity, so links and bind mounts count; purge checks the same).
- `runlock`: advisory lock at `<config path>.lock` marking a live appliance,
  so token commands use its API instead of editing its config.
- `atomicfile`: atomic durable file replace (config, certs).
- `update`: the appliance side of updates. `Manager` is a `monitor.Monitors`
  member (daily check gated on `updates.check`, the available notification,
  one-button apply); `Fetcher` resolves the latest tag once and verifies the
  manifest pair; `Stager` stages the release in `<cert dir>/update/`;
  `Applier` is the root updater (`service apply-update`, started by
  `remote-mic-update.path`), which re-verifies everything through an
  `os.Root`, swaps the binary, and rolls back unless the new version writes
  its health file from the unit's main process and stays up for a settle
  period; `Boot` reports the outcome and writes that file.
  `WithdrawOrphanedRequest` runs at startup, before the API, and withdraws a
  request an earlier process left unclaimed. `Install.RerunInstall` words
  every hint to re-run `service install`, and names the service binary only
  when it passes the root-only check. The file names and
  JSON fields here are contracts between versions (root file, Releases).
- `releasemanifest`: the signed release manifest schema, Ed25519 signing and
  verification, and the trusted release keys. Platform-neutral, standard
  library only, shared by the release tool and update code.
