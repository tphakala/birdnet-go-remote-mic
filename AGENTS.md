# AGENTS.md

Instructions for AI coding agents (Claude Code, Antigravity/Gemini, and others)
working in this repository. `CLAUDE.md` imports this file, so keep project
guidance here and only here.

## What this is

`remote-mic` (module `github.com/tphakala/birdnet-go-remote-mic`) is a pure-Go,
zero-CGO, single-static-binary remote microphone appliance for
[BirdNET-Go](https://github.com/tphakala/birdnet-go). It captures audio from
local ALSA devices and serves it over a self-implemented TCP-interleaved
RTSP/RTP server, advertised over mDNS (`_rtsp._tcp`). It also runs an HTTPS
management API and an embedded web UI.

- Stream modes: `opus` (48 kHz, mono or stereo, normal audio) and `pcm` (raw
  L16 at the capture rate, up to 384 kHz, for ultrasonic bat detection).
- One capture per device, fanned out to one or more RTSP streams, each with its
  own path, mode, and channel subset.
- Targets: Linux only. arm64 is primary (Pi Zero 2 W and up), 32-bit arm
  (GOARM=6, older Pis) is a release target, amd64 is for development.
- Go 1.27. No `replace` directives; the module builds from public sources.

## Sibling libraries (same author, public)

- `github.com/tphakala/go-audio-capture`: pure-Go ALSA capture (ioctl level).
- `github.com/tphakala/go-audio-stream`: RTSP message layer and send primitives
  (RTP/RTCP marshal, `packet/l16`, `packet/opus`, SDP writer).
- `github.com/tphakala/go-opus`: pure-Go Opus encoder.

A bug that lives in capture, RTSP framing, or the codec usually belongs in one
of those repos, not here.

## Build, test, and the gate

```
task check        # the full local gate; run it before every push
```

`task check` runs: `web:verify` (tsc type-check, oxlint, html-validate a11y
audit, node:test unit tests, web build), builds for amd64 + arm64 + arm with
CGO off, `go vet` on amd64/arm64/arm/386, golangci-lint, `api:lint` (vacuum),
`api:verify` (generated code matches the spec), gofmt, and `go test -race`.

`web/dist` is generated by `task web:build` and is NOT committed. Bare `go`
commands need either the compiled assets or the stub UI:

```
CGO_ENABLED=0 go build -tags skipfrontend ./...
go test -race -tags skipfrontend ./...
golangci-lint run ./...          # .golangci.yaml already sets skipfrontend
```

Other useful tasks: `task test`, `task lint`, `task fmt`, `task web:test`,
`task api:generate`. The web toolchain is pinned in `Taskfile.yml` and run via
`npx -p`; there is no `package.json` or `node_modules` to install.

Tests must pass on a machine with or without a sound card: never let a unit
test open real ALSA hardware. Use `audio.NewFakeSource` and the existing seams.

## Layout

- `cmd/remotemic`: the `remote-mic` binary (all files `//go:build linux`).
  Subcommands: `serve` (default), `token`, `devices`, `service`, `version`.
  `--config` defaults to `$REMOTEMIC_CONFIG`, else `./config.yaml`.
  `appliance.go` wires capture, pipeline, RTSP, monitors, and reload.
  `default.pgo` is the committed PGO profile (see "Releases").
- `internal/config`: YAML config and strict `Validate`. Invalid input fails
  loudly at startup; never degrade silently. `Enabled` and `QuietAlert` are
  `*bool` (nil means default on). The legacy flat single-stream device form is
  migrated to `streams:` on load; `Save` always writes the nested form.
- `internal/audio`: the `Source` interface (`Negotiated`/`Read`/`Close`)
  delivering S16LE periods. Linux `OpenCapture` negotiates S16LE, then S32LE,
  S24_LE, S24_3LE, downconverting to S16. It refuses a rate mismatch (honest-rate
  policy: never resample silently). Devices are bound by stable identity (USB
  vendor/product/serial/port), not ALSA card index. `fanout.go` splits one
  capture into per-stream channel subsets.
- `internal/pipeline`: `Stage` turns periods into RTP payload frames: `NewPCM`
  (L16 passthrough) and `NewOpus` (960-sample frames). `Frame.Captured` carries
  the capture wall-clock time.
- `internal/rtspserver`: minimal RTSP server, one playing client per path.
  Absolute-URI routing, SETUP echoes the client-chosen interleaved channels,
  PLAY returns RTP-Info. `writer.go` is the single writer per connection.
  `ChanSource` only buffers while a client is playing (active flag).
- `internal/announce`: DNS-SD advertisement (brutella/dnssd). Advertise only.
- `internal/mgmtapi`: GENERATED by oapi-codegen from `api/openapi.yaml`. Never
  edit by hand; change the spec and run `task api:generate`.
- `internal/mgmtserver`: server side of the management API, adapting live state
  from a `Provider` into the generated contract.
- `internal/mgmtcert`: self-signed TLS cert on first start, regenerated when
  missing/expired/wrong names; a custom installed cert is pinned.
- `internal/auth`: one shared token gates both HTTP (Bearer) and RTSP (Digest).
  Empty token means open access.
- `internal/sse`: platform-neutral SSE transport. Producers implement `Source`;
  producers import `sse`, never the reverse.
- `internal/levels`: per-device peak/RMS metering, central sampler, fan-out hub.
- `internal/notify`: in-memory notification center (bounded ring plus active
  conditions). Leaf package; emitters depend on `Publisher`, and a nil
  `*Center` is a no-op. History is RAM-only by design.
- `internal/monitor`: condition monitors (audio signal, host health) and the
  `Settings`/`SettingsFrom`/`Monitors.Apply` seam fed on every reload.
- `internal/reload`: pure, platform-neutral planning of how to reconcile a
  running appliance to a new config without restarting. Keep it pure.
- `internal/sysinfo`: `/proc`, `/sys`, and statfs readers for `GET /system` and
  the host monitor. Parsers are platform-neutral; readers are Linux-only.
- `internal/service`: installs a systemd unit running as a least-privilege
  system user (deb-family today).
- `internal/runlock`: advisory lock beside the config marking a live appliance,
  so token commands go through its API instead of editing a file it will
  overwrite.
- `internal/atomicfile`: atomic durable file replace (config, certs).
- `web/`: vanilla TypeScript UI (no framework, no bundler), compiled by `tsc`
  and embedded with `go:embed` (`web/embed.go`; `embed_skipfrontend.go` is the
  stub). Pure logic lives in `web/src/lib/*-core.ts` and is unit-tested in
  `web/test/` with `node:test`. Views: dashboard, system, events.
- `api/openapi.yaml`: the OpenAPI 3.1 contract, committed as source.
- `rules/rules.go`: gocritic ruleguard rules used by the linter.

## Architecture rules

- The sound card is the clock. The capture read loop drives everything; there
  is no pacer. The capture pump runs on a `runtime.LockOSThread` goroutine.
- Stamp RTCP Sender Reports from `Frame.Captured`, never from send time, or TCP
  backpressure skews the receiver's clock.
- The RTP hot path writes into a reused buffer with a 4-byte interleave prefix.
  Do not call `rtsp.MarshalInterleaved` per RTP packet (it allocates); it is
  acceptable once per SR interval. Avoid allocations per period in general: the
  target hardware is a Pi Zero 2 W.
- Config changes apply live through `internal/reload`; prefer in-place
  reconciliation over process restarts.
- Keep platform-neutral packages free of Linux-only imports; put Linux-only
  code in `//go:build linux` files so vet on every GOARCH stays green.

## Management API conventions

- `/api/v1` is additive-only: never remove or repurpose a field or endpoint.
- Errors are RFC 9457 `application/problem+json`.
- Wire schemas use camelCase; YAML config uses snake_case.
- Live data (levels, notifications) is SSE-only on one multiplexed
  `GET /api/v1/events` with a named `heartbeat` event every 15 s. The web UI
  reads it with `fetch` streaming because `EventSource` cannot send an
  `Authorization` header.
- After editing the spec: `task api:lint`, `task api:generate`, then commit the
  regenerated `internal/mgmtapi/gen.go` together with the spec.

## Web UI conventions

- Accessibility is a gate, not a nicety: `web:a11y` and the contrast token test
  run in CI. Keep keyboard focus, labels, and contrast intact.
- Put logic that can be tested without a DOM into a `*-core.ts` module with a
  matching test in `web/test/`.

## Code style

- Go: gofmt, golangci-lint clean (config in `.golangci.yaml`), comments explain
  why rather than restating what. Match the density and tone of nearby code.
- Never use em dashes or en dashes anywhere (code, comments, docs, commits).
  Use commas, colons, semicolons, parentheses, or a plain hyphen.
- Commit subjects follow Conventional Commits with a scope where it helps:
  `feat(audio): ...`, `fix(service): ...`, `docs: ...`, `ci: ...`. Hard-wrap
  commit bodies at about 72 columns.
- Pull request descriptions are GitHub Markdown: one line per paragraph, no hard
  wrapping.

## Workflow

- Code changes go through a pull request and are squash-merged. Docs-only,
  formatting-only, and config/metadata changes may go straight to `main` after
  `task check` passes.
- Design documents, plans, specs, and research notes are never committed.
  `docs/` is gitignored for that purpose; keep such notes there locally.
- The public roadmap and bug tracker are the GitHub issues on this repository.
  Reference them as `#123` in PRs and commits.
- Keep `README.md` accurate when a change alters user-visible behavior, config,
  or install steps.

## Releases

Tags `v*` are built by GoReleaser (`.goreleaser.yaml`, `.github/workflows/release.yml`):
Linux amd64/arm64/arm (GOARM=6) tarballs, `.deb` packages, and a Homebrew
formula pushed to `tphakala/homebrew-tap`. Builds use
`-pgo=cmd/remotemic/default.pgo` by explicit path (not `-pgo=auto`), so a
missing profile fails the release instead of silently shipping a non-PGO
binary. The profile is GOARCH-independent. Collect a new one from a running
appliance with `remote-mic serve --pprof 127.0.0.1:6060` (unauthenticated, so
bind it to loopback only).

## Gotchas

- go-audio-capture: `Negotiate` must issue PREPARE after SW_PARAMS, or Start
  returns EBADFD. ioctl struct sizes and numbers are verified against
  `sound/asound.h` separately for LP64 and ILP32; do not guess them.
- go-audio-stream `rtsp.Client.Dial` only sends OPTIONS; a test client must call
  `Describe`, `Setup`, and `Play` explicitly to receive frames.
- `go get` with a branch name containing a slash fails ("disallowed version
  string"); pin with a commit SHA instead.
- Notification timestamps are wall-clock; a Pi without an RTC can step its clock
  after NTP syncs, so do not assume timestamps are monotonic.
- Local test servers: use free high ports (18000 and up), track the PIDs you
  start, and only kill those. Never kill a process just because it holds a port
  or sound device you wanted.
